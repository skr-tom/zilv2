# 自律 4.2

Android + Jetpack Compose。页面固定五个：**每日任务、长期计划、日历、每日小记、设置**。
专注模式不占导航页，点任务的「开始」后自动进入全屏专注。

---

## 第四轮优化（本次改动）：应用内更新（OTA）

从这一版开始，升级**不用卸载旧版、不用自己去找 APK**：App 自己检查新版本 → 后台下载 → 拉起系统安装界面 → 覆盖安装。

### 用户看到的流程

1. 打开 App 时静默检查一次（12 小时内不重复）；也可在「设置 → 版本更新」点「检查更新」。
2. 有新版本时弹出版本号、安装包大小、更新内容；可以「立即更新」「稍后」「跳过此版本」。
3. 系统下载管理器在后台下载 APK，**切到桌面也不中断**，App 内显示百分比进度。
4. 下载完成发一条通知，点通知直接进安装界面（App 内也会弹「立即安装」）。
5. 在系统安装界面点一次「安装」，覆盖完成，重新打开就是新版本。

### 「不用卸载」为什么成立

- 数据存在应用私有目录 `SharedPreferences("zilu_v4")`，覆盖安装原样保留：任务、长期计划、日历待办、每日小记、铃声和所有设置都在。
- Android 覆盖安装只有两个硬条件：**签名一致** + **versionCode 递增**。每次发版用同一把 keystore、`versionCode` 比上一版大即可。
- 为此 `app/build.gradle.kts` 加了可选签名配置：根目录放 `keystore.properties` 就用它签 release；没放则统一用 `debug` 签名，保证和历史手动安装的包签名一致。**千万别中途换签名**。

> 两个必须说清楚的边界：
> 1. **4.1.0 → 4.2.0 仍需手动装一次**（旧版里没有更新模块），从 4.2.0 起才能真正「App 内更新」。
> 2. Android 强制要求用户点一次系统「安装」确认，普通应用**无法静默安装**。但不需要卸载、不需要自己下载 APK、数据不会丢。

### 发布一个新版本要做的 5 件事

1. 改代码，`app/build.gradle.kts` 里 `versionCode` +1、`versionName` 改成新版本号。
2. **Build > Build Bundle(s) / APK(s) > Build APK(s)** —— 用同一台电脑、同一个 Android Studio / 同一把 keystore，得到已签名 APK。
3. 把 APK 传到能直链下载的地方（GitHub Release 的 Assets、自己的服务器、对象存储）。
4. 编辑仓库里的 `update.json`（模板见 `update.example.json`），改 `versionCode` / `versionName` / `apkUrl` / `changelog`，提交推送。
5. 用户打开 App 就会收到更新提示。

`update.json` 字段：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `versionCode` | ✅ | 整数，必须**大于**用户当前版本才会提示 |
| `versionName` | 推荐 | 展示用，例如 `4.3.0` |
| `apkUrl` | ✅ | APK 的 https 直链 |
| `changelog` | 推荐 | 更新内容，支持 `\n` 换行 |
| `force` | 可选 | `true` 时不显示「稍后 / 跳过」，适合修严重 bug |
| `sizeBytes` | 可选 | 安装包字节数，用于弹窗里显示大小 |

### 更新地址

默认 `https://raw.githubusercontent.com/skr-tom/zilv2/main/update.json`，在「设置 → 版本更新 → 更新地址」里可改成任意静态 JSON 地址（Gitee、自己的服务器、内网 http 都行，manifest 已允许明文流量）。

两点提醒：
- 先确认仓库默认分支是 `main` 还是 `master`，把地址里的 `main` 改成实际分支，否则会 404（手动检查会提示「检查失败」，自动检查则静默跳过）。
- `raw.githubusercontent.com` 在国内手机网络时不稳；如果收不到更新提示，把 `update.json` 和 APK 放到 Gitee 或自己的服务器，再把设置页的更新地址改过去即可。

也兼容 **GitHub Releases latest API**：把地址填成
`https://api.github.com/repos/skr-tom/zilv2/releases/latest`，
会自动取 `tag_name`、`body` 和 `assets` 里第一个 `.apk`。此时 `versionCode` 按 tag 推算（`v4.3.0` → `40300`），也可以在 Release 说明第一行写 `versionCode: 7` 显式指定。

### 权限说明

| 权限 | 用途 |
| --- | --- |
| `INTERNET` | 拉取版本清单、下载 APK |
| `REQUEST_INSTALL_PACKAGES` | Android 8+ 从 App 内拉起安装界面 |
| 「安装未知应用」开关 | 系统级开关，首次更新时 App 会引导用户打开一次；设置页也有「去开启」入口 |

APK 下载到应用私有外部目录 `Android/data/com.zilu.app/files/Download/`，经 FileProvider 暴露，**不需要存储权限**。下载完成后 `UpdateReceiver` 发安装通知；即使个别 ROM 拦了这条广播，系统下载管理器自身的「下载完成」通知、App 前台的进度轮询、以及下次打开 App 时的待安装检查，也都能把用户带到安装界面。

新增文件：`AppUpdater.kt`（版本检查 / 下载 / 进度 / 安装 / 通知）、`UpdateReceiver.kt`（下载完成与包替换收尾）、`ui/UpdateHost.kt`（检查对话框、进度、授权引导）、`update.example.json`、`keystore.properties.example`。

## 第三轮优化

| # | 需求 | 实现 |
| --- | --- | --- |
| 1 | 三级都能改名、完成心得可折叠、文件夹可自由移动 | 文件夹 / 计划 / 子计划标题旁都加「修改」按钮，弹出统一编辑框（文件夹还能改配色，子计划还能改月/日）；完成心得改成默认收起的折叠区；文件夹标题左侧加拖动把手，**默认按最后修改时间倒序**（刚改过的自动置顶），拖动后按新顺序固定 |
| 2 | 完成度算错了 | 文件夹进度改为 **`已完成计划数 / 计划总数`**，子计划勾选不再计入；副标题同步换成「N 个计划 · 已完成 M 个」 |
| 3 | 昨天没做完的待办要顺延到今天 | `TodoItem` 增加 `originalDate`；每次读取数据时把「过去日期且未完成」的待办平移到今天，直到勾选完成为止；列表里标出「顺延自 M/D · 未完成」 |
| 4 | 专注切后台，状态栏要看到 logo 和时间 | 专注通知渠道换成新 ID 并提到 `IMPORTANCE_HIGH`（静音不振动）；修正 Chronometer 的 `setWhen` 基准（之前误用墙上时钟，倒计时显示是错的）；标题 / 正文 / Ticker 直接写 `mm:ss`，每 5 秒刷新一次，彩色沙漏大图标 + 白色沙漏小图标常驻 |

### 关于「专注时状态栏显示」

App 侧能做的是：让常驻通知**在状态栏有图标、锁屏可见、下拉里有彩色 logo 和实时倒计时**，并把它标成计时类（`CATEGORY_STOPWATCH`）+ `IMPORTANCE_HIGH`，这样国产 ROM 的「超级岛 / 原子通知 / 灵动岛」才有机会把它显示在挖孔区。挖孔胶囊本身由系统绘制，是否出现取决于手机厂商，App 无法强制。

之前看不到的两个真原因：
- 专注渠道是 `IMPORTANCE_LOW`，多数国产 ROM 会把这类前台服务通知的状态栏图标折叠/隐藏；Android 又不允许修改已建渠道的重要性，所以必须换渠道 ID（`zilu_focus_v5`），旧的 `zilu_focus_v4` 会自动清掉。
- `setUsesChronometer(true)` 时 `setWhen` 需要 `SystemClock.elapsedRealtime()` 基准，旧代码传的是 `System.currentTimeMillis()`，算出来是几千年的倒计时，等于没有时间；同时通知只在启动时构建一次，从不刷新。

| 7 | 第二级计划可独立勾选完成 | `Plan` 增加 `done` / `completedAt` 并持久化；计划卡片标题左侧加圆形勾选框，勾选后标题加删除线、进度计入文件夹，与子计划状态互不依赖 |

### 关于「到点不震动」的根因

Android 8+ 之后通知的声音/振动由**通知渠道**决定，而不少国产 ROM 会直接忽略渠道里的 `vibrationPattern`；
另外旧代码里「提醒时振动」这个开关虽然存在，却完全没有接到通知链路上，关掉响铃时走的还是一条 `enableVibration(false)` 的渠道。

这轮做了四层修复：

1. 渠道拆成三条：`响铃 + 振动` / `仅振动` / `静音`，按「提醒时响铃」「提醒时振动」组合自动选。
2. 通知 builder 上再显式写一次 `setVibrate`（兼容旧版本与部分 ROM）。
3. **主动调用系统 `Vibrator`** 振一次（截止提醒、专注完成、测试通知各一次），绕开 ROM 对渠道振动的拦截 —— 这是最关键的一层。
4. 用户自选铃声写入「任务截止提醒」「专注完成」两个渠道；换铃声时删掉旧渠道重建（渠道创建后系统不允许改声音）。自定义 URI 读不到时自动回退系统默认音，不会变成哑巴。

设置页「铃声与振动」里四项开关：**提醒时响铃 / 提醒时振动 / 完成任务时响铃 / 完成任务时振动**，加上「提醒铃声 → 选择」入口。

## 首轮升级做了什么

### 1. 通知（重点修复）

之前的推送不生效，主要原因有四个，已逐项处理：

| 问题 | 现象 | 现在的做法 |
| --- | --- | --- |
| 通知小图标用的是系统资源 `android.R.drawable.*` | 在 Android 8+ / 国产 ROM 上被渲染成白块或直接不显示 | 自绘白色沙漏矢量图 `ic_stat_zilu.xml`，并把沙漏 Logo 作为大图标显示在通知右侧 |
| 提醒渠道重要性是 `LOW` | 通知被折叠到通知栏底部，不弹横幅、锁屏看不到 | 「任务截止提醒」「专注完成」都改为 `IMPORTANCE_HIGH` |
| 沿用了旧渠道 ID | 用户曾经关掉过渠道，重建同名渠道不会恢复 | 渠道 ID 全部换成 `_v4`，并自动清理旧的 `_v2` 渠道 |
| 只用 `SCHEDULE_EXACT_ALARM` | 用户没去设置里手动授权时，退化成不精确闹钟，Doze 下可能延迟十几分钟 | 增加 `USE_EXACT_ALARM`（Android 13+ 系统直接授予） |

另外：

- 提醒通知的 ID 按任务固定，不会每天堆一条。
- 设置页有**通知自检面板**：通知权限、两个渠道是否被关、精确闹钟、电池优化，逐项显示状态并提供「去开启」按钮；「发一条测试通知」后询问是否收到，收到即收起该面板。
- 专注时的常驻通知加了 `FOREGROUND_SERVICE_IMMEDIATE`，切后台后立即出现在通知栏，并带一个「退出专注」按钮。

### 2. 专注中途退出按秒扣时

任务按秒存 `durationSeconds`（计划时长）和 `remainingSeconds`（剩余时长）。

- 计划 1 分钟，专注 30 秒后退出 → 任务剩 `0:30`，卡片显示「已做一部分，还剩 0:30」，按钮变成「继续」。
- 下次点「继续」从 30 秒接着计时；正常走完才写入完成记录并把时长复原。

### 3. 提醒时间改为手动输入

「__ 时 : __ 分」两个数字输入框，校验 0~23 / 0~59，填错时保存按钮禁用。

### 4. 长期计划三级

```
文件夹（第一级，每个文件夹一套颜色）
└── 计划（第二级，嵌在文件夹卡片里，可独立勾选完成）
    └── 子计划（第三级，唯一可以设「完成日期-月-日」的一层）
```

- 二级计划直接列在一级文件夹卡片内部，点计划展开第三级子计划。
- 只有子计划有「月 / 日」手动输入框，可以为空；过了日期标红「已逾期」。
- 文件夹有 8 套配色，卡片底色、图标、进度条跟着变。

### 5. 日历

- 月历卡片：月份前后翻页，点日期行跳到任意年月，周一为一周第一天。
- 每个日期格子最多显示 **3 条**当天待办的彩色标签，超过显示 `+N 更多`。
- 下方待办卡片：左侧彩色拖拽把手 + 浅色底 + 右侧方形勾选框。
- **上下拖动**：按住左侧色条拖动调整顺序，松手写入顺序；拖动过程中其它卡片整行让位，不会重叠。
- **完成后自动沉底**：绿色 ✓ 并自动排到最下面，未完成的往上走。
- 长按标题删除该条待办。

### 6. 每日小记

- 顶部日期行可点开**日期选择器**，能补写任意一天；每天内容独立保存。
- 停止输入 0.6 秒自动保存到当前选中日期；下方「往期小记」按日期倒序，点开可继续写。
- 不是今天时显示「回到今天」。

## 构建

用 Android Studio 打开 `zilu-4.1` 根目录（不是 `app`），等待 Gradle Sync 完成后
**Build > Build Bundle(s) / APK(s) > Build APK(s)**。

- 需要 JDK 17（Android Studio 自带）、compileSdk 35。
- 仓库里没有放 `gradle-wrapper.jar`，命令行 `./gradlew` 需要先执行一次 `gradle wrapper`；
  直接用 Android Studio 构建则不受影响。
- **签名一致性是应用内更新的前提**，每次发版必须用同一把签名，二选一：
  1. 最省事：一直用同一台电脑、同一个 Android Studio 构建 **debug 包**，它用固定的 `debug.keystore` 签名，天然一致；
  2. 正式一点：把 `keystore.properties.example` 复制成 `keystore.properties`，按里面的 `keytool` 命令生成 `release.jks`，之后每次都用这把签 release 包。
  未配置 `keystore.properties` 时，`release` 会自动回落到 debug 签名。**一旦发过版就不要换签名**，否则用户只能卸载重装。
- 当前版本 `versionCode = 6 / 4.2.0`；每次发版 `versionCode` 必须比上一版大，否则不会提示更新。

## 装好之后建议做的三件事（国产 ROM 尤其重要）

1. 首次启动点「允许」通知权限。
2. 设置页 →「铃声与振动」→ 点「提醒铃声」选一个本地铃声；再到「通知与提醒」逐项检查，点「发一条测试通知」，**确认有响铃和振动后点「收到了」**（之后自检面板就不再出现）。
3. 小米 / 华为 / OPPO / vivo 再到系统设置里给「自律」打开**自启动**、**后台弹出界面**，电池策略选**不限制**。

## 数据兼容

存储 key 为 `zilu_v4`，本轮新增的字段都有默认值，旧数据不会丢：

- 旧任务的「分钟」转成秒级时长；
- 旧计划统一放进「我的计划」文件夹，旧子目标转成子计划；
- 旧待办的排序在读取时按日期规整一次（未完成在前、已完成沉底），统一改用 `sortOrder` 表达；
- 本轮新增的 `autoCheckUpdate` / `updateUrl` / `skippedVersionCode` 都有默认值，旧数据读出来就是「开启自动检查 + 默认更新地址」。
